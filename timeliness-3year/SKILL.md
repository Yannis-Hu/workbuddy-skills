# 时效性约束（Timeliness-3year）

本 skill 不产出独立交付物，而是一套**覆盖当次任务全流程的执行约束**。用户发布复杂任务并提到「时效性」时，从任务开始到输出全程遵守本原则。

## 触发条件

用户消息中包含「时效性」「3 年以内」「信息必须最新」等表达，且同时给出（或随后给出）一个待执行任务时，立即激活本约束。激活后在当次会话回复开头用一句话告知用户：「已启用时效性约束：所有信息源限近 3 年，超期信息将标注提示」。

## 核心规则（全程强制）

**基准时刻** = 用户发布该指令的时间（以会话中的当前时间为准，不是任务中途的时间）。

1. **默认拒绝旧信息**：所有引用的信息源（网页、报告、新闻、政策、数据、价格、任职信息等）发布/更新时间必须在基准时刻起 3 年以内。
2. **超期信息 = 提示 + 标注**：确实重要且无法用新信息替代的 3 年以前信息，允许使用，但必须：
   - 在使用处紧跟标注具体年月（如「（2022-06 数据）」），格式参考：`来源名 YYYY-MM`；
   - 在正文流中或结尾用醒目方式向用户提示，例如：「⚠️ 以下 X 处引用了 3 年以前的信息，已标注具体时间，请谨慎引用：…」
3. **无法判定时效 → 视为超期处理**：来源发布时间查不到的，按「时间不明」处理，标注「时间不明，未能核实」，不得冒充新信息。
4. **优先级排序**：同一事实有多个来源时，选最新的；新数据与旧数据冲突时，以新数据为准，旧数据仅作对比时明确标注年份。
5. **政策/价格/人事类信息从严**：招聘窗口、政策条款、价格、公司高管/组织变动等易变信息，尽量收敛到 12 个月以内，并提示用户以最新官方公告为准。

## 执行方式

1. **任务开始前**：识别任务涉及的每类信息（数据、观点、政策、面经等），为每类设定时效检查点。
2. **检索阶段**：使用 WebSearch/WebFetch 时优先带时间过滤（freshness 限 1 年内优先）；打开来源时核对发布日期，无日期的来源降级处理。
3. **输出阶段**：每个关键结论旁标注「来源，年份」；超期引用按核心规则第 2 条处理。
4. **收尾自检**（输出前必做）：
   - [ ] 逐条核对所有引用的时间戳，是否有漏标年份的
   - [ ] 超期信息是否全部向用户提示
   - [ ] 结尾附「信息截至日期：YYYY-MM-DD」

## 输出中的标注格式

- 3 年以内：`（来源名 YYYY-MM）` 或表格「来源」列 `来源名，年份`
- 3 年以上（允许保留的）：`（来源名 YYYY-MM，⚠️ 超过 3 年，请谨慎引用）`
- 时间不明：`（来源时间不明，未能核实）`

## 边界情况

- 用户明确说「可以用旧数据对比」时，旧信息可正常引用，但仍需标注年份并在对比处说明新旧差异。
- 纯创作类任务（无外部信息）不适用本约束，回复说明即可。
- 用户指定了其他时效窗口（如「只要近 1 年」）时，以用户指定为准，本 skill 的 3 年规则作为默认值。
