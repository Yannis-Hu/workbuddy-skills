# 行业分析_test

对用户指定的单一行业产出一份可直接阅读的结构化分析文本。重点是「数字有出处、口径说得清、可放心引用」。

**本 skill 不预设使用场景**。分析用途由用户声明或经助手追问确认；未确认时按通用中性口径输出，不得把「分析一个行业」默认等同于求职/面试准备。

## 触发条件

当用户说「帮我分析这个行业」「行业分析：XX」或等效表达，并给出一个行业名称时，按本流程执行（格式无需再确认，但**用途需要按第 0 步处理**）。

## 工作流程

### 第 0 步：明确分析用途（必做，先于其他步骤）

- **不预设、不脑补用途**。「分析一个行业」可能是面试准备、投资判断、竞品对标、市场进入评估、选题研究，也可能只是想了解。用户未说明时不套用任何单一场景。
- **只有用途会实质影响取舍时才追问**：若用途会改变口径选择或信息详略（是否需要下游应用/岗位视角、是否要按投资口径补充估值与标的、是否只要结论不要数据），用一次提问确认，给出 2–3 个候选用途。**不影响时直接执行，不要为了确认而确认。**
- **用途未确认时的硬约束（不可放宽）**：
  - 标题、正文、结尾提示中不得出现「面试」「求职」「简历」「面试弹药」等场景化措辞；
  - 不得自行添加「如何使用本文」「面试使用建议」一类用途导向的章节；
  - 输出保持通用分析口径：数字带来源与年份、推测与事实分开、口径争议已标注。
- 用户明确说明用途后，方可按该场景调整取舍。

### 第 1 步：明确分析对象

- 确认行业名称及其边界（如「协同办公」与「SaaS」不同，「企业级 AI」需明确含不含消费级）。
- 用户未说明时，按中国内地市场为主口径，并在开头声明口径。
- 行业名称含糊（如只说「AI」）时，先向用户追问一次，列出 2–3 个候选口径供选择；不脑补。

### 第 2 步：联网调研（多轮检索）

使用 WebSearch/WebFetch 至少覆盖以下检索面，每个面 1–2 轮：

1. 行业定义与发展历史（关键节点、转折事件）
2. 市场规模：权威咨询机构（艾瑞、IDC、Gartner、亿欧、头豹等）近 2 年报告，优先一手机构发布
3. 竞争格局：主要玩家及最新年份份额
4. 未来 3–5 年预测与机构观点
5. 近 12 个月的标志性事件（融资、产品发布、政策）

检索要求：
- 优先 3 年以内信息；超过 3 年的必须标注具体年份。
- 交叉验证：关键数字至少两个独立来源，或明确标注「单一来源」。
- 二手汇总（媒体转述报告）要标注「经 XX 引述」，并提示引用需谨慎。

### 第 3 步：按模板输出

读取 `references/output-template.md`，严格按其四个模块输出纯文本（Markdown）：

1. **标题行**：行业名 + 一句话定位（中性描述行业边界，如「XX 行业（含 XX 细分赛道）」，不得写成「岗位所在的行业」）
2. **发展脉络**：一段话，按时间线叙述，关键转折加粗
3. **关键指标表格**：4 列（指标 / 数值 / 口径·时点 / 来源），4–6 行
4. **未来 3–5 年潜力**：机构观点，标明属分析性内容，每条带来源+年份
5. **可引用亮点**：3–4 条加粗开头的短句，每条带来源+年份（**不得标注为「面试弹药」或其他场景化标签**）

### 第 4 步：可信度自检（输出前必做）

逐条检查：
- [ ] 每个数字都有来源 + 年份；找不到来源的数字直接删除，不猜测
- [ ] 份额、规模等有争议数字标注口径争议
- [ ] 机构观点与事实分开表述
- [ ] 全文没有编造的报告名、媒体名；不确定的来源写「未能核实」
- [ ] 结尾附「信息截至日期：YYYY-MM-DD」

## 输出规范

- 简体中文，直接输出文本，不生成文件（除非用户要求）。
- 先给核心结论（1–2 句行业判断），再展开四模块。
- 表格来源列格式：`机构/媒体名，年份`。
- **用途未确认时全文保持中性**：任何场景化的标题、提示或增值章节都不得由助手单方面添加（详见第 0 步硬约束）。
- 全文控制在 600–900 字（不含表格），保证可读性。
