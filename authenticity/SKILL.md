# 真实性约束（Authenticity）

本 skill 不产出独立交付物，而是一套**覆盖当次任务全流程的执行约束**。用户发布复杂任务并提到「真实性」时，从任务开始到输出全程遵守本原则。

## 触发条件

用户消息中包含「真实性」「真实可溯源」「不要编造」「必须有依据」等表达，且同时给出（或随后给出）一个待执行任务时，立即激活本约束。激活后在当次会话回复开头用一句话告知用户：「已启用真实性约束：事实将标注来源与年份，无法核实的会直接说明，推测将明确标注」。

## 核心规则（全程强制）

1. **所有事实可溯源**：每条关键结论标注来源，来源类型限定为「官方公告 / 企业官网 / 权威媒体 / 行业报告」四类之一，并同时注明：
   - 信息发布年份（如「界面新闻 2026-08」）
   - 你的核查日期（格式 `核查于 YYYY-MM-DD`）
2. **无法核实就直说**：查不到、拿不准、来源存疑的内容，直接写「无法核实」，不用推测填充，不为了内容完整而编造。以下四类**尤其从严**：
   - 岗位是否存在（招聘岗位真实性）
   - 薪资数字
   - 内推机会
   - 政策条款
3. **区分事实与推测**：事实标注来源；你的经验判断、行业常识、主观建议，明确标为「推测 / 经验判断」，不得混入事实陈述。

## 执行方式

1. **任务开始前**：识别任务会涉及的每类事实性信息，明确哪些必须有来源、哪些允许经验判断。
2. **检索阶段**：优先一手来源（官方公告、企业官网、权威媒体、行业报告），二手转述降级并标注「经 XX 引述」；优先 3 年以内信息（可与 timeliness-3year 叠加使用）。
3. **输出阶段**：关键结论旁标注来源 + 年份 + 核查日期；经验判断标「推测 / 经验判断」。
4. **收尾自检**（输出前必做）：
   - [ ] 每条关键结论是否都有来源或已标「无法核实」
   - [ ] 岗位/薪资/内推/政策四类是否逐条核对
   - [ ] 是否还有没标「推测」的主观判断
   - [ ] 结尾附「核查日期：YYYY-MM-DD」

## 输出中的标注格式

- 可溯源事实：`（来源类型：机构/媒体名，YYYY-MM；核查于 YYYY-MM-DD）`
- 无法核实：`（无法核实）`，并说明原因（来源缺失/口径不明/时间不明）
- 推测/经验判断：`（推测 / 经验判断）`

## 边界情况

- 用户明确要求「先给我快速判断」时，可降低逐条标注密度，但仍需在结论前声明「以下含推测，未逐条标注来源」。
- 纯创作类任务（无外部事实）不适用本约束，回复说明即可。
- 用户已给出明确一手材料（如用户自述、指定文档）时，以该材料为准，来源标注为「用户提供」。
