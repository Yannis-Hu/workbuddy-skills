# 企业分析

对用户指定的单一企业产出一份可直接阅读的结构化分析文本。重点是「数据有出处、分析有框架、结论可溯源」。

**本 skill 不预设使用场景**。分析用途（面试准备、投资判断、竞品对标、合作评估、纯了解信息……）必须由用户声明或经助手追问确认；未确认时一律按通用中性口径输出，不得把「分析一家企业」默认等同于求职/面试准备。

## 触发条件

当用户说「帮我分析这个企业」「企业分析：XX」或等效表达，并给出一家企业名称时，按本流程执行。

## 工作流程

### 第 0 步：明确分析用途（必做，先于其他步骤）

- **不预设、不脑补用途**。「分析一家企业」可能是面试准备、投资判断、竞品对标、合作或采购评估，也可能只是想了解一家公司。用户未说明时不套用任何单一场景。
- **只有用途会实质影响取舍时才追问**：若用途会改变框架选择或信息详略（是否需要估值或投资建议、是否保留或弱化波特五力与波士顿矩阵、是否需要针对某类岗位做适配），用一次提问确认，并给出 2–3 个候选用途。**不影响时直接执行，不要为了确认而确认。**
- **用途未确认时的硬约束（不可放宽）**：
  - 标题、正文、结尾提示中不得出现「面试」「求职」「简历」「面试弹药」等场景化措辞；
  - 不得自行添加「如何使用本文」「面试使用建议」「投资建议」一类用途导向的章节；
  - 输出保持通用分析口径：事实可溯源、推测已标注、框架不空套。
- 用户明确说明用途后，方可按该场景调整取舍；即便在求职场景中，也只提供可溯源的事实与有依据的判断，不替用户下结论。

### 第 1 步：明确分析对象

- 确认企业全称、上市状态（上市/未上市）、所在行业。
- 同名企业（如「小米」vs「小米集团」vs「小米汽车」）先向用户确认分析主体，不脑补。

### 第 2 步：联网调研（多轮检索）

使用 WebSearch/WebFetch 至少覆盖以下检索面：

1. **核心数据**：员工人数、最近一年（最近完整财年）营收及同比、所处赛道排名/市占率
2. **股权与组织**：前五大股东及持股、实控人、组织架构（事业部/子公司结构）
3. **业务模式**：全部业务线及各业务营收占比；主营业务详情
4. **高管与战略**：近 12–24 个月高管公开讲话、财报电话会、战略发布会披露的未来方向
5. **前景素材**：行业趋势、机构研报、竞争动态、公司重点投入方向

检索要求：
- 上市公司优先读最近年报/季报及交易所披露文件，标注报告期（如「2025 年报」）。
- 未上市公司数据标「未上市，数据为估算/披露口径」。
- 所有关键数字带来源+年份；无法核实的直接写「无法核实」。

### 第 3 步：按五模块输出

读取 `references/output-template.md`，严格按以下结构输出纯文本（Markdown）：

#### 模块 1：核心数据
表格列出：员工人数、上一年营收（及同比增速）、所处赛道排名/市占率，每项带来源+报告期。

#### 模块 2：股权结构和组织架构
- 股权：前五大股东及持股比例、实控人、是否上市及上市地。
- 组织：主要事业部/子公司架构，用缩进列表呈现层级。

#### 模块 3：业务模式
- **a. 业务全景**：列出全部业务线，标明各业务营收/规模占比（来源：财报分部数据）。
- **b. 主营业务波特五力分析**：对主营业务逐力分析——现有竞争者、潜在进入者、替代品、供应商议价力、购买者议价力，每力 1–2 句并附判断强弱。
- **c. 波士顿矩阵（仅产品型公司）**：将各产品/业务按市场增长率×相对份额放入明星/金牛/瘦狗/问号四象限，用文本表格呈现。非产品型公司（如纯服务）标注「非产品型，跳过波士顿矩阵」。

#### 模块 4：高管发言与未来发展方向
摘录近 12–24 个月高管（CEO/CFO/董事长）公开发言、财报会、战略发布中关于未来方向的表述，每条附（来源，年月）。

#### 模块 5：第三方视角前景分析（明确标「分析性内容」）
从第三方客观视角分析：①发展趋势；②重点投入方向；③潜在机遇方向。每条标注「推测 / 经验判断」或机构观点来源。

### 第 4 步：可信度自检（输出前必做）

- [ ] 每个数字带来源 + 报告期/年份；查不到写「无法核实」
- [ ] 未上市 vs 上市口径已区分
- [ ] 模块 5 的推测均标「推测 / 经验判断」，与事实分开
- [ ] 波特五力、波士顿矩阵结论有依据，不空套框架
- [ ] 结尾附「信息截至日期：YYYY-MM-DD」

## 输出规范

- 简体中文，直接输出文本，不生成文件（除非用户要求）。
- 先给核心结论（1–2 句企业判断），再展开五模块。
- 表格来源列格式：`机构/媒体名，年份`。
- **用途未确认时全文保持中性**：任何场景化的标题、提示或增值章节都不得由助手单方面添加（详见第 0 步硬约束）。
- 可与 `authenticity`（真实性）、`timeliness-3year`（时效性）约束技能叠加使用。
